     3→# 🧠 Candidate-to-Job Matching Engine Documentation
     4→
     5→## Version: Phase 2 Technical Architecture (v2.0 – Comprehensive)
     6→
     7→---
     8→
     9→## Core Principle
    10→
    11→The platform uses the following principle:
    12→
    13→**AI-on-Ingest, CPU-on-Match**
    14→
    15→This means:
    16→
    17→- AI or parser logic is used when a CV or job is uploaded.
    18→- The uploaded CV or job post is converted into structured data.
    19→- Structured data is saved in MySQL.
    20→- Matching is done using SQL joins and scoring logic.
    21→- AI is not used repeatedly during matching.
    22→- CV files are not permanently stored.
    23→
    24→This keeps the platform scalable, cheap, and fast.
    25→
    26→---
    27→
    28→## 1. Product Vision
    29→
    30→The platform helps candidates discover jobs that match their real skills, qualifications, experience, and career interests.
    31→
    32→The goal is not to match only job titles.
    33→
    34→The goal is to understand:
    35→
    36→- What the candidate can do
    37→- What the job requires
    38→- What category of work the role belongs to
    39→- What subcategory or specialization the role belongs to
    40→- What skills are required
    41→- What qualifications are required
    42→- What the candidate is interested in
    43→- What jobs are realistic for the candidate
    44→
    45→---
    46→
    47→## 2. Matching Philosophy
    48→
    49→The system separates:
    50→
    51→- Organization type
    52→- Organization industry
    53→- Job category
    54→- Job subcategory
    55→- Role title
    56→- Skills
    57→- Tools
    58→- Qualifications
    59→- Experience
    60→- Candidate preferences
    61→
    62→### Example
    63→
    64→Kenyatta National Hospital is in the healthcare industry.
    65→
    66→But if they hire an HR Officer:
    67→
    68→- Organization industry: Healthcare
    69→- Job category: Human Resources
    70→- Job subcategory: HR Generalist or Recruitment
    71→- Role: HR Officer
    72→
    73→The candidate does not need to be a healthcare worker.
    74→
    75→They need to be an HR professional.
    76→
    77→Therefore:
    78→
    79→Industry is context.
    80→
    81→Category and subcategory are strong matching signals.
    82→
    83→Skills and qualifications are proof.
    84→
    85→---
    86→
    87→## 3. Why Industry Has Low Matching Weight
    88→
    89→A professional can work across many industries.
    90→
    91→Example:
    92→
    93→An HR Officer can work in:
    94→
    95→- Healthcare
    96→- Banking
    97→- Telecommunications
    98→- Education
    99→- Government
   100→- Manufacturing
   101→- NGO
   102→
   103→A Finance Officer can work in:
   104→
   105→- NGO
   106→- Government
   107→- Healthcare
   108→- Banking
   109→- Manufacturing
   110→- Education
   111→
   112→So industry should not dominate matching.
   113→
   114→Recommended use:
   115→
   116→- Industry familiarity is a small bonus.
   117→- It should not reject otherwise good candidates.
   118→- Category, subcategory, skills, and qualifications should carry more weight.
   119→
   120→---
   121→
   122→## 4. Final Matching Weights
   123→
   124→Recommended scoring model:
   125→
   126→```js
   127→const MATCH_WEIGHTS = {
   128→  categoryMatch: 25,
   129→  subcategoryMatch: 25,
   130→  skillsMatch: 25,
   131→  qualificationsMatch: 10,
   132→  experienceMatch: 10,
   133→  industryFamiliarity: 5
   134→};
   135→```
   136→
   137→Total: 100%
   138→
   139→Meaning:
   140→
   141→- Category match checks if the candidate is in the same career function.
   142→- Subcategory match checks specialization.
   143→- Skills match checks capability.
   144→- Qualifications match checks eligibility.
   145→- Experience match checks level.
   146→- Industry familiarity gives a small contextual bonus.

   150→## 5. System Architecture
   151→
   152→### Candidate Upload Flow
   153→
   154→```txt
   155→Candidate uploads CV
   156→        ↓
   157→Backend receives file in memory
   158→        ↓
   159→Markitdown extracts Markdown/text
   160→        ↓
   161→Parser extracts structured data
   162→        ↓
   163→Optional AI fallback if parser confidence is low
   164→        ↓
   165→Normalize data against taxonomy
   166→        ↓
   167→Save structured profile to MySQL
   168→        ↓
   169→Discard uploaded file
   170→        ↓
   171→Run CPU-based matching
   172→        ↓
   173→Save top matches
   174→        ↓
   175→Return candidate profile + matches
   176→```
   177→
   178→---
   179→
   180→### Job Upload Flow
   181→
   182→```txt
   183→Recruiter uploads job post
   184→        ↓
   185→Backend receives job text
   186→        ↓
   187→Parser or AI extracts structured job profile
   188→        ↓
   189→Normalize against taxonomy
   190→        ↓
   191→Save job and job profile to MySQL
   192→        ↓
   193→Run CPU-based matching against candidates
   194→        ↓
   195→Save candidate-job scores
   196→```
   197→
   198→---
   199→
   200→## 6. No Media Storage Rule
   201→
   202→CV files should not be permanently stored.
   203→
   204→The file should be:
   205→
   206→1. Uploaded.
   207→2. Processed in memory.
   208→3. Converted to text.
   209→4. Discarded.
   210→
   211→The database stores:
   212→
   213→- Extracted name
   214→- Email
   215→- Phone
   216→- Skills
   217→- Education
   218→- Work experience
   219→- Qualifications
   220→- Career category
   221→- Subcategories
   222→- Matching data
   223→
   224→The database should not store the original CV file unless a future business requirement requires it.
   225→
   226→Optional:
   227→
   228→You may store raw extracted CV text for debugging for a short period, for example 30 days.

   232→## 7. AI Role in the System
   233→
   234→AI should not be the main matcher.
   235→
   236→AI is used for:
   237→
   238→### 7.1 CV Extraction
   239→
   240→AI helps convert messy CVs into structured data.
   241→
   242→Example:
   243→
   244→```txt
   245→Finance Intern at PATH Kenya
   246→Managed Accounts Payable, reconciliations, audit schedules...
   247→```
   248→
   249→Becomes:
   250→
   251→```json
   252→{
   253→  "category": "FINANCE_ACCOUNTING",
   254→  "subcategories": ["ACCOUNTING", "ACCOUNTS_PAYABLE", "AUDIT"],
   255→  "skills": ["ACCOUNTS_PAYABLE", "BANK_RECONCILIATION", "AUDIT_SUPPORT"],
   256→  "tools": ["ERP_SYSTEMS", "EXCEL"],
   257→  "industriesWorkedIn": ["INTERNATIONAL_DEVELOPMENT", "NON_PROFIT"]
   258→}
   259→```
   260→
   261→### 7.2 Job Extraction
   262→
   263→AI helps extract structured job requirements.
   264→
   265→Example:
   266→
   267→```txt
   268→Part-Time Lecturer required for Community Health, Counselling Psychology, Social Work...
   269→```
   270→
   271→Becomes:
   272→
   273→```json
   274→{
   275→  "jobCategory": "EDUCATION",
   276→  "jobSubcategories": ["LECTURING", "TVET_TRAINING"],
   277→  "specializations": [
   278→    "COMMUNITY_HEALTH",
   279→    "COUNSELLING_PSYCHOLOGY",
   280→    "SOCIAL_WORK"
   281→  ]
   282→}
   283→```
   284→
   285→### 7.3 Normalization
   286→
   287→AI or parser logic maps different wording to the same taxonomy item.
   288→
   289→Examples:
   290→
   291→```txt
   292→Talent Acquisition → Recruitment
   293→People Operations → HR Operations
   294→Quick Books → QuickBooks
   295→Accounts Clerk → Accounting
   296→IT Helpdesk → IT Support
   297→```
   298→
   299→### 7.4 Transferable Skills Detection
   300→
   301→AI helps detect career transitions.
   302→
   303→Examples:
   304→
   305→```txt
   306→Cashier + CPA + reconciliation → Accounts Assistant
   307→Radio Presenter + Social Media → Communications Officer
   308→Enumerator + Data Collection → M&E Assistant
   309→```
   310→
   311→### 7.5 Explanation
   312→
   313→After the algorithm calculates the score, AI can explain the match.
   314→
   315→Example:
   316→
   317→```txt
   318→You are a strong match because your CV shows Accounts Payable, Bank Reconciliation, CPA progression, and financial reporting experience.
   319→
   320→Your main gap is SAP experience, which was not found in your CV.
   321→```

   373→## 9. Taxonomy Model
   374→
   375→The taxonomy is the foundation of the matching engine.
   376→
   377→It stores:
   378→
   379→- Organization types
   380→- Industries
   381→- Job categories
   382→- Subcategories
   383→- Roles
   384→- Skills
   385→- Tools
   386→- Qualifications
   387→- Certifications
   388→- Specializations
   389→
   390→### 9.1 taxonomy_items
   391→
   392→```sql
   393→CREATE TABLE taxonomy_items (
   394→  id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
   395→
   396→  type ENUM(
   397→    'ORGANIZATION_TYPE',
   398→    'INDUSTRY',
   399→    'CATEGORY',
   400→    'SUBCATEGORY',
   401→    'ROLE',
   402→    'SKILL',
   403→    'TOOL',
   404→    'QUALIFICATION',
   405→    'CERTIFICATION',
   406→    'SPECIALIZATION',
   407→    'REGULATION',
   408→    'COMPETENCY'
   409→  ) NOT NULL,
   410→
   411→  value VARCHAR(120) NOT NULL,
   412→  label VARCHAR(255) NOT NULL,
   413→
   414→  parent_id BIGINT UNSIGNED NULL,
   415→
   416→  description TEXT NULL,
   417→
   418→  is_active BOOLEAN NOT NULL DEFAULT TRUE,
   419→
   420→  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
   421→  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
   422→
   423→  UNIQUE KEY unique_taxonomy_value (type, value),
   424→
   425→  INDEX idx_taxonomy_type (type),
   426→  INDEX idx_taxonomy_parent (parent_id),
   427→
   428→  CONSTRAINT fk_taxonomy_parent
   429→    FOREIGN KEY (parent_id)
   430→    REFERENCES taxonomy_items(id)
   431→    ON DELETE SET NULL
   432→);
   433→```
   434→
   435→Example rows:
   436→
   437→```txt
   438→CATEGORY: HUMAN_RESOURCES
   439→SUBCATEGORY: RECRUITMENT
   440→SKILL: CANDIDATE_SCREENING
   441→TOOL: QUICKBOOKS
   442→QUALIFICATION: BACHELOR_DEGREE
   443→INDUSTRY: HEALTHCARE
   444→```

   482→### 9.3 taxonomy_relationships
   483→
   484→This supports adjacent career relationships.
   485→
   486→Example:

   491→HR is related to Administration

   504→    'ADJACENT',
   505→    'TRANSFERABLE',
   506→    'PARENT_CHILD',
   507→    'SIMILAR'
   508→  ) NOT NULL DEFAULT 'RELATED',
   509→
   510→  weight DECIMAL(4,2) NOT NULL DEFAULT 1.00,
   511→
   512→  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
   513→
   514→  UNIQUE KEY unique_relationship (source_item_id, target_item_id, relationship_type),

   517→    FOREIGN KEY (source_item_id)

   520→
   521→  CONSTRAINT fk_relationship_target
   522→    FOREIGN KEY (target_item_id)
   523→    REFERENCES taxonomy_items(id)
   524→    ON DELETE CASCADE
   525→);

  1785→### 18.2 Subcategory Match (✅ UPDATED)
  1786→
  1787→```js
  1788→function calculateSubcategoryMatch(candidate, job) {
  1789→  // Primary subcategory match = highest score
  1790→  if (candidate.primarySubcategoryId === job.primarySubcategoryId) {
  1791→    return 100;
  1792→  }
  1793→
  1794→  // Check candidate's extracted subcategories against job's subcategories
  1795→  const candidateSubcategories = candidate.subcategoryIds;
  1796→  const jobSubcategories = job.subcategoryIds;
  1797→
  1798→  if (!jobSubcategories.length) return 0;
  1799→
  1800→  const matched = jobSubcategories.filter(id =>
  1801→    candidateSubcategories.includes(id)
  1802→  );
  1803→
  1804→  const score = (matched.length / jobSubcategories.length) * 100;
  1805→
  1806→  // If candidate has it as an interest, boost slightly
  1807→  if (candidate.interestCategoryIds.includes(job.jobCategoryId)) {
  1808→    return Math.min(score + 10, 100);
  1809→  }
  1810→
  1811→  return score;
  1812→}
  1813→```

  1939→
  1940→  -- ✅ UPDATED: Subcategory Score (Weight: 25%)
  1941→  CASE
  1942→    -- Highest: Primary subcategory matches
  1943→    WHEN jp.primary_subcategory_id IS NOT NULL
  1944→      AND cp.primary_subcategory_id = jp.primary_subcategory_id

  1947→    -- High: Candidate's extracted subcategories match job's subcategories
  1948→    WHEN EXISTS (
  1949→      SELECT 1
  1950→      FROM job_subcategories js

  1952→        ON cs.candidate_id = ca.id
  1953→        AND cs.subcategory_id = js.subcategory_id

  1957→    -- Medium: Candidate has the job's category as an interest

  1959→      SELECT 1
  1960→      FROM candidate_interests ci

  1962→        AND ci.category_id = jp.job_category_id

  1965→    ELSE 0
